# whatsnext feature list
Date: 2026-11-06 (UTC). Status: proposed. Merged from feature-candidates.md and competitive-reuse.md. Code is written fresh; "approach" cells name a solved problem to follow, not code to copy.

## How to read this

- Impact is value adjusted for the rightsize framing (rightsize decides when to wrap up or compact; whatsnext decides what is kept and writes the files): High, Med or Low. Effort is S, M or L.
- Rows are sorted by Impact high to low inside each group, ties broken by lower effort first, then by row number. Row numbers 1 to 26 match the earlier files.
- Impact was lowered for rows 7 and 10 to 13 (planning beyond step completion) and row 14 (helps two-agent use, not the rightsize pairing). Source ranges were set to one value: row 24 High (was Med to High), row 25 Low (was Low to Med), row 22 effort M (was S to M).
- "Approach to follow" names a solved problem and the one thing to learn from it. "none" means no tool or doc shows a better way.

## Build order

1. Rows 4 + 20 + 26: the Claude Code PreCompact text. Auto-compact is the top complaint, row 20 caps the text so it cannot flood, and row 26 tests the output shape. Codex gets only the fact line and the resume note.
2. Row 6: the latest request, read at PreCompact and never stored. It is the most named loss at compaction and is now effort S.
3. Row 5: the facts-only keep-list. It guides every compact when no `wrap up` happened, which is the usual auto-compact case.
4. Row 8: verify records the code state. It is the one planning row that answers "is it proven", and the data already exists in git.
5. Row 24: the dead ends line. It is a cheap quality gain for the handoff and the compact text, and needs an ADR amendment.

Next picks: row 14 if two-agent use matters more than quality; rows 3 and 16 are small label changes to take with row 4 if the note has room. Row 27 is a good sixth pick: small, and it stops a plan edit from leaving a stale claim.

| Cross-session memory, fact extraction, semantic recall, hosted or vector store | claude-mem [32], Mem0 [33] | ADR-0001 items 2, 4, 5: no memory, no model call, no database or background process. |
| Issue graph, atomic claim, ready queue, dependency types, Dolt storage | Beads [34], Task Master [36] | Whatsnext tracks step completion only; ADR-0001 "Not in this release" lists tracker adapters and cross-machine claims. Row 13 stays low. |

| Context-size reminder at a token threshold | prep-compact [24], agent-handoff [27] | rightsize decides when (ADR-0010 item 1). |
| Model pass that writes decisions, constraints, blockers at compact time | prep-compact skill [24] | ADR-0001 item 4: no model call; the agent writes the note on `wrap up`. |
| Spawning a fresh session or tab and waking it | claude-handoff by MarcinSufa [31], REMvisual [26] | A hook cannot start a model turn, it is editor specific, and ADR-0009 item 1 says whatsnext never submits into another process. |
| Replacing the conversation with the handoff (no summarizer call) | REMvisual `/compact-handoff` [26] | Needs a mod and Claude Code internals; the compact stays the person's or rightsize's action. |
