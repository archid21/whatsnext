# Feature candidates for whatsnext
Date: 2026-11-06 (UTC). Status: proposed, unverified unless a row says otherwise.

## Summary

The loudest pain in the sources is context lost at compaction, mostly auto-compact: the summary forgets what is done and what is left, drops the latest multi-part request, and nothing tells the user it happened [2][3][4][5]. Users already work around it with handoff files, and they forget to write them [12]. The second pain is "done" claims that no run backs, most often a pass reported after later edits [8][9]. The third is plan and multi-agent drift: plans lost at compact, and worktrees that stop file clashes but not duplicate work [7][14]. Rows 4 to 6 answer the first, rows 7 to 9 the second, rows 10 to 13 and 19 the third. Claude Code's PreCompact hook can inject compact instructions through stdout, so row 4 is buildable now [1].

### Row 4 note: what PreCompact can do

Claude Code's hooks reference, section "PreCompact" [1]:

- It can inject instructions. "When a PreCompact hook exits 0 and doesn't block, Claude Code uses its stdout as instructions for the compaction summary." The cap is 10,000 characters per hook.
- Input fields: `trigger` (`manual` or `auto`) and `custom_instructions` (the user's `/compact` text; `null` for `auto` or when none is given).
- It can block: exit code 2 or `"decision": "block"`. Blocking an auto-compact that fires near the limit can make the request fail, so whatsnext should not block.
- It cannot: show the user a message (`systemMessage` and `continue` are discarded), start a model turn (so it cannot run `wrap up`), or change the result after the fact. PostCompact gets `compact_summary` but has no decision control.
- Not stated in the docs: whether stdout is added to, or replaces, a user's own `/compact <text>`. Test this before shipping row 4.
- Codex lists `PreCompact` and `PostCompact` too, and says PreCompact "can stop" compaction [16]. The page does not say whether stdout becomes instructions on Codex. Treat Codex injection as unverified.

## Recommended first five

1. Row 4 (with row 5): auto-compact is the most reported pain, and the hooks reference confirms PreCompact stdout becomes compact instructions [1]. Row 5 makes the text useful when no handoff exists.
2. Row 8 (with row 9, one patch): a stale pass is the main false-done cause in the measured data [8], and a verify command may be piped by a person.
3. Row 7: it is the only candidate that moves the "agents skip the commands" limit from a note to a check, and both agents expose a pre-edit hook.
4. Row 6: the latest request is the single most named loss at compaction [4], and the hook already receives the prompt.
5. Row 14: cheap, and it stops one session's wrap-up from erasing another's note in two-agent use.

Rows 3 and 16 are small label changes worth taking with row 4 if the note has room. Rows 1 and 2 add little: row 2 is mostly built, and row 1 has no matching complaint.

## Out of scope (ADR-0001)

- Cross-project memory, fact extraction and semantic recall (claude-mem, Mem0). ADR-0001 item 2 excludes them.
- Search over past conversations (HN users parse session JSONL into a database [12]). ADR-0001 item 2 excludes it.
- A model-written summary at each Stop. ADR-0001 item 4 (no model call) and "Not in this release".
- A hook that runs `wrap up` or `/compact` by itself. A hook cannot start a model turn [1]; rightsize does this by choice (ADR-0010).
- Cross-machine or shared claims (a SQLite plan store, a Dolt graph [14][17]). ADR-0001 "Not in this release" lists cross-machine claims.
- Tracker adapters (GitHub, Beads, Jira). ADR-0001 lists them as needing a new decision.
- Blocking compaction from PreCompact. ADR-0005 item 1 says a hook never breaks a session.
- Reloading `CLAUDE.md` after compaction [2][5]. Rules files are not whatsnext's job (ADR-0001 item 2), and Claude Code has an `InstructionsLoaded` hook for it [1].
- Compacting closed sessions with a cheap model. ADR-0009 item 5 keeps it off the public release.
