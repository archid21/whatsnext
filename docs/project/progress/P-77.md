## Hook events (from official docs)

### Gemini CLI

- Config files. User `~/.gemini/settings.json`; project `.gemini/settings.json` (project beats user; also `/etc/gemini-cli/settings.json` and extensions). https://geminicli.com/docs/hooks/
- Config shape: `{"hooks": {"<Event>": [{"matcher": "<regex or exact or * or empty>", "hooks": [{"name": "...", "type": "command", "command": "...", "timeout": <ms, default 60000>, "description": "..."}]}]}}`. `type` must be `command`. Same group shape as Codex, timeout in milliseconds. https://geminicli.com/docs/hooks/
- Master switch: `hooksConfig.enabled` (default true). https://geminicli.com/docs/cli/settings/
- Event map (internal -> Gemini):
  - session start -> `SessionStart` (startup, resume, clear). https://geminicli.com/docs/hooks/
  - prompt -> `BeforeAgent` (after the prompt is submitted, before planning). https://geminicli.com/docs/hooks/
  - turn end -> `AfterAgent` (when the agent loop ends). https://geminicli.com/docs/hooks/
  - before compact -> `PreCompress`. https://geminicli.com/docs/hooks/
  - session end -> `SessionEnd`. https://geminicli.com/docs/hooks/
  - Not mapped: `BeforeTool` could carry the plan-tick guard (Codex `pre-edit`); not in P-77 scope.
- Stdin, every event: `session_id`, `transcript_path` (absolute, session transcript JSON), `cwd`, `hook_event_name`, `timestamp` (ISO 8601). https://geminicli.com/docs/hooks/reference/
  - SessionStart adds `source` (startup|resume|clear). Gap: no `compact` source.
  - BeforeAgent adds `prompt`. AfterAgent adds `prompt`, `prompt_response`, `stop_hook_active`.
  - PreCompress adds `trigger` (auto|manual). SessionEnd adds `reason` (exit|clear|logout|prompt_input_exit|other).
  - Page: https://geminicli.com/docs/hooks/reference/ and https://github.com/google-gemini/gemini-cli/blob/main/docs/hooks/reference.md
- Output: stdout must be one JSON object only (any other stdout text is read as a `systemMessage`); logs go to stderr. Exit 0 = parse stdout; exit 2 = block (stderr is the reason); other = non-fatal warning. https://geminicli.com/docs/hooks/
  - SessionStart: `{"systemMessage": "...", "hookSpecificOutput": {"additionalContext": "..."}}`; `additionalContext` is injected as the first turn in history (prepended to the prompt when non-interactive). Advisory; startup is never blocked.
  - BeforeAgent: `{"hookSpecificOutput": {"additionalContext": "..."}}` is appended to the prompt for this turn only.
  - AfterAgent: no `additionalContext` (it has `decision: deny` + `reason` to force a retry, and `hookSpecificOutput.clearContext`). Gap for context.
  - PreCompress: only `systemMessage` (shown to the user); advisory, cannot block or change compression. Gap for model context.
  - SessionEnd: only `systemMessage`; best effort, the CLI does not wait.
  - Page: https://geminicli.com/docs/hooks/reference/ and the GitHub reference above.
- Env vars for hooks: `GEMINI_PROJECT_DIR`, `GEMINI_SESSION_ID`, `GEMINI_CWD`, alias `CLAUDE_PROJECT_DIR`. https://geminicli.com/docs/hooks/
- Management: `/hooks panel`, `/hooks enable|disable <name>`. https://geminicli.com/docs/hooks/
- Not found in the docs read: any trust prompt for project hooks (page says nothing), per-event JSON examples for settings.json `additionalContext`.

### Cursor

- Config files. User `~/.cursor/hooks.json`; project `<project-root>/.cursor/hooks.json`; enterprise (MDM) and team (cloud) levels also exist. Priority enterprise > team > project > user; all matching hooks run. Cursor reloads on save (restart if it does not). Project hooks run only in a trusted workspace. https://cursor.com/docs/hooks
- Config shape: `{"version": 1, "hooks": {"<eventName>": [{"command": "...", "type": "command|prompt", "timeout": <seconds>, "loop_limit": 5, "failClosed": false, "matcher": "<regex>"}]}}`. `version` is required (positive integer, use 1). No matcher group level: each event holds a flat list of handlers. Timeout in seconds. https://cursor.com/docs/hooks
- Event map (internal -> Cursor):
  - session start -> `sessionStart`. https://cursor.com/docs/hooks
  - prompt -> `beforeSubmitPrompt` exists, but its output is only `continue` and `user_message`; it cannot add context. Gap for prompt-time wrap-up instructions. https://cursor.com/docs/hooks
  - turn end -> `stop` (status completed|aborted|error, loop_count). https://cursor.com/docs/hooks
  - before compact -> `preCompact` (observational; cannot block or change compaction). https://cursor.com/docs/hooks
  - session end -> `sessionEnd`. https://cursor.com/docs/hooks
- Stdin, every event: `conversation_id`, `generation_id`, `model`, `hook_event_name`, `cursor_version`, `workspace_roots` (list), `user_email`, `transcript_path`. `cwd` is NOT in the common fields (only tool and shell events have it). https://cursor.com/docs/hooks
  - sessionStart adds `session_id`, `is_background_agent`, `composer_mode`. Gap: no `source` (start/resume/clear/compact are not told apart).
  - beforeSubmitPrompt adds `prompt`, `attachments`. stop adds `status`, `loop_count`.
  - preCompact adds `trigger` (auto|manual) and context-size fields. sessionEnd adds `session_id`, `reason`, `duration_ms`, `final_status`.
- Output (exit 0, JSON on stdout): https://cursor.com/docs/hooks
  - sessionStart: `{"env": {...}, "additional_context": "..."}`; `additional_context` is "added to the conversation's initial system context". Fire-and-forget (the loop does not wait).
  - beforeSubmitPrompt: `{"continue": bool, "user_message": "..."}` only. Gap for context.
  - stop: `{"followup_message": "..."}` is auto-submitted as the next user message. Not used by whatsnext.
  - preCompact: `{"user_message": "..."}` shown to the user. Gap for model context.
  - sessionEnd: no output fields.
- Exit codes: 0 = use JSON; 2 = block; other = hook failed, action proceeds (unless `failClosed`). https://cursor.com/docs/hooks
- Env vars: `CURSOR_PROJECT_DIR`, `CURSOR_VERSION`, `CURSOR_TRANSCRIPT_PATH`, alias `CLAUDE_PROJECT_DIR`. https://cursor.com/docs/hooks

### Unclear in the docs (decisions taken, see Open questions)

- Cursor: the docs do not say whether `session_id` (sessionStart, sessionEnd) equals `conversation_id` (all events). whatsnext uses `conversation_id` as the session id when present, else `session_id`.
- Cursor: no event can put text in front of the model at prompt time, so `wrap up` instructions and the post-compact resume note cannot arrive by hook. Cursor gets the instructions tier for those (`wn wrap-up-instructions`).
- Gemini: PreCompress cannot return model context and SessionStart has no `compact` source, so the resume note after a compress arrives at the next BeforeAgent (the same marker Codex uses).
